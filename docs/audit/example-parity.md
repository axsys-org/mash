# Example parity acceptance inventory

Audited 2026-09-08 against the supplied reference documentation and local gallery
source, revision `48336016a3074fbb8af619014b18565ef747f512`. This extends the existing
[capability checklist](../reference/components.json) and
[structural census](inventory.md); it does not replace either with tag counts.
The checklist's example names are historical mappings, not verified current
coverage. In particular, later refinement overrides can remove mapped examples.

This pass inspects controls, navigation, overlays, and display examples in
`apps/catalog/src/examples/{controls,components,navigation,utility,patterns,refinements}.ts`
and the corresponding component implementations. The update also inspects
`keyboard.ts`, `control-patterns.ts`, and `menus.ts`, including their effective
merge into the catalogue. Reference evidence comprises
`website/component/<topic>.md` and `crates/story/src/stories/<topic>_story.rs` from
the supplied source. Source-backed absence means the current effective examples
do not demonstrate a feature; it does not imply the component cannot support it.
No rows below certify visual equivalence. Matching captures and interaction
acceptance in light and dark themes remain required.

Priority: **P0** broken interaction or lost coverage; **P1** conspicuous missing
reference examples/behaviors; **P2** deeper variants, composition, or polish.

were visually reviewed in both themes; this remains scoped acceptance, not a
catalogue-wide visual-equivalence claim.

## Acceptance and continued inventory

For every row, retain existing useful variants and add consolidated, directly
visible examples. Each behavior example needs an observable result, a reset path
when it mutates sample state, pointer and keyboard behavior, and readable states
in both themes. Dense state matrices may share one example; related interactions
must not disappear behind an example selector.

Stage acceptance is independent of component acceptance: controls and overlays
must have enough logical width/height, one obvious scroll owner, an expandable
window, reversible zoom, and preserved state when expanded. The preview-window
implementation now supplies shared chrome, expansion/restoration and zoom; its
existence does not certify every component has enough usable space. Compare at the same
logical viewport before judging visual equivalence; zoom must not disguise
clipped content or replace responsive behavior.

Outstanding topic owners must append equivalent evidence for chart/plot, tables,
calendar/date, dock/resizing/virtualization, editor/color selector/shimmer, and
conversation. Existing mappings for root/theme/focus trap are integration topics,
not reasons to create decorative elements. All 71 checklist topics remain under
reference acceptance until their actual variants, interactions, and matching
captures are verified. The historical `review: reference-comparison-pending`
status is still the correct aggregate claim.
