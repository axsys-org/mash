# Example parity acceptance inventory

Audited 2026-09-08 against the supplied reference documentation and local gallery
source, revision `48336016a3074fbb8af619014b18565ef747f512`. This extends the existing
[capability checklist](../reference/components.json) and
[structural census](inventory.md); it does not replace either with tag counts.
The checklist's example names are historical mappings, not verified current
coverage. In particular, later refinement overrides can remove mapped examples.

This pass inspects controls, navigation, overlays, and display examples in
`apps/catalog/src/examples/{controls,components,navigation,utility,patterns,refinements}.ts`
and the corresponding component implementations. Reference evidence comprises
`website/component/<topic>.md` and `crates/story/src/stories/<topic>_story.rs` from
the supplied source. Source-backed absence means the current effective examples
do not demonstrate a feature; it does not imply the component cannot support it.
No rows below certify visual equivalence. Matching captures and interaction
acceptance in light and dark themes remain required.

Priority: **P0** broken interaction or lost coverage; **P1** conspicuous missing
reference examples/behaviors; **P2** deeper variants, composition, or polish.

## Verified failures and the first repair batch

- **P0 Pagination:** the only `Pagination` sample has no `ui-page-change` listener.
  `UIPagination` is controlled, so page requests do not update its selected page.
- **P0 Avatar:** `componentExamples` appends `patternExamples` and subsequently
  overwrites the avatar array with `refinements`. The existing `Group` example
  becomes unreachable. A hardcoded `+3` also does not demonstrate a real limit.
- **P1 Accordion:** the supplied gallery explicitly places live switches and
  checkboxes in its expanded content. Mash's four samples cover disclosure and
  nesting, but almost all panels contain passive prose. Add a usable panel that
  demonstrates independent form controls and preserved state across collapse.
- **P1 Tabs:** five appearances and four sizes exist, but the implementation has
  no reorder behavior or overflow-selection menu. Dock tabs do not establish
  parity for `ui-tabs`. The adjacent Back/Add buttons in the example have no handlers.
- **P1 Keyboard hints:** the source gallery includes Default and Outlined
  treatments and punctuation chords. Mash has `key` and `plain` appearances;
  neither an independently documented outlined treatment nor punctuation/binding
  examples establish the full reference behavior.

The repair batch implements pagination, the live accordion panel, and avatar group
restoration. It does not close the remaining rows. The tables below preserve the
initial findings as acceptance requirements; implementation is not acceptance.

Implemented during this pass:

- `Pagination` now renders a controlled slice of 60 documents; `Page windows`
  adds independently controlled first/middle/last examples plus disabled state.
- `Interactive panels` adds an editable preview title, description switch,
  notification checkbox, and instructions for testing retained state.
- Refinements apply before composition patterns, restoring `Group`;
  `Group limits` adds a real member list, visible-limit slider, and numeric or
  ellipsis overflow with accessible hidden-member names.

Production checks now verify pagination status and document rows, independent
accordion controls and retained input after collapse/reopen, restored group
coverage, and changing member limits and ellipsis overflow. These are part of the
20 passing focused showcase/interaction checks. They establish behavior for this
repair batch; visual parity and the remaining variants below are still open.

## Acceptance and continued inventory

For every row, retain existing useful variants and add consolidated, directly
visible examples. Each behavior example needs an observable result, a reset path
when it mutates sample state, pointer and keyboard behavior, and readable states
in both themes. Dense state matrices may share one example; related interactions
must not disappear behind an example selector.

Stage acceptance is independent of component acceptance: controls and overlays
must have enough logical width/height, one obvious scroll owner, an expandable
window, reversible zoom, and preserved state when expanded. Compare at the same
logical viewport before judging visual equivalence; zoom must not disguise
clipped content or replace responsive behavior.

Outstanding topic owners must append equivalent evidence for chart/plot, tables,
calendar/date, dock/resizing/virtualization, editor/color selector/shimmer, and
conversation. Existing mappings for root/theme/focus trap are integration topics,
not reasons to create decorative elements. All 71 checklist topics remain under
reference acceptance until their actual variants, interactions, and matching
captures are verified. The historical `review: reference-comparison-pending`
status is still the correct aggregate claim.
