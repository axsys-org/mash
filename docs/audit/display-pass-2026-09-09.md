counts, line numbers and “missing” descriptions describe that baseline, not the

### Repaired behavior and evidence

- Image: assigning a fallback after a failed unchanged primary now starts the
  fallback request. Promoting an already-loaded fallback URL to primary retains
  loaded state and emits updated primary metadata without waiting for a native
  load event that will never repeat for an unchanged URL. The actual image
  regression covers both transitions. Responsive-source selection is excluded
  from that same-resource shortcut.
- Editor: source ranges map through native before-input context and separate
  indentation/replacement changes. Committed native change is forwarded once
  across the shadow boundary. Source/editor/image checks passed **21 tests** in
  three files; four focused production editor scenarios await integrated
  acceptance rather than standing in for visual comparison.
- Button: native disabled-fieldset state is retained separately from authored
  `disabled`; effective state gates form actions, host/native clicks, focus and
  presentation. The final callback state is reconciled after reflected updates,
  preventing a button from remaining disabled after its authored attribute is
  removed. **40 button source tests passed**, including first-legend exemption,
  submit/reset/link-variant behavior and disable/reenable transitions.
- The earlier production display run passed six workflows: upload lifecycle,
  resizable persistence, notification undo/key identity, navigation persistence,
  toolbar statistics/save and marker draft preservation. Its image failure
  motivated the latest repair. That older result is not a pass for the final
  image build or the exhaustive production sweep now in progress.

UI/catalogue source typechecking, focused lint/formatting and token-consumer
checks passed at their respective source checkpoints. These checks establish
source contracts, not pixel fidelity. Remaining broad gaps include settings
page/search behavior, title-bar/root setup and standalone focus-trap teaching.
No Stories implementation or registration is counted as component closure.

The effective list comes from [examplesFor](../../apps/catalog/src/examples.ts), not a count of `sample()` calls:

1. `controlExamples[tag]` takes precedence over `componentExamples[tag]`.
2. Component collections spread utility/data/table/conversation entries, then replace explicit entries. Refinements replace earlier entries. Pattern and menu collections append afterward.
3. At the initial baseline, controls also appended matching patterns, including toolbar “Status bar”. The current reconciliation above records its subsequent replacement with the functional toolbar list.
4. Composition aliases expose one chosen parent example. `ui-accordion-item`, `ui-dock-panel`, and both resizable anatomy routes therefore show only the first parent section. This does not make every parent variant visible on every child route.
5. A direct curated list suppresses the manifest's examples. A documented API, unit test, or suppressed JSDoc snippet is not evidence that its state is visible in the catalogue.

Gap labels: **E** = missing or incomplete effective example; **A** = public behavior/anatomy or shared recipe needs work or an explicit mapping decision; **H** = host/platform behavior requiring an explicit web adaptation; **V** = visual comparison remains unverified. Every row retains **V**; additional labels identify concrete source findings.

## Initial baseline: consolidation and visibility findings

The shared fake window now has the right structural direction: sections are consolidated and can share zoom/expanded browsing. That does not make missing sections appear. This pass makes no new measured claim about scroll performance or available stage space; the parent task owns that review.

- **Preserve composition examples that teach state.** Interactive accordion panels, avatar image recovery/group limits, dock moves preserving drafts, and settings submit/reset are useful additions. They should remain alongside direct variant grids.
- **Promote supported but invisible states.** Badge dot/icon/zero, label highlighting/masking, shimmer styling, progress indeterminate, image recovery and toast-stack placement/limits already have public behavior. Their direct routes should expose it before new primitives are considered.
- **Do not confuse appended content with replacement.** Avatar has five effective sections, not only the three refinement sections. Toolbar has four, including Status bar. The present assembly fixes those earlier visibility issues. Conversely, each anatomy alias still selects only one parent example; provide clear navigation to the full owner rather than duplicating every complex frame under every child tag.
- **Make actions truthful.** The unconnected Card Open project, Toast Undo, toolbar Publish/New/Save and status controls need an observable local result or passive presentation. Fragment-only navigation does not show a destination changing in the demo.
- **Expose related compositions where users look.** Description-list treatment lives under Card, status under Toolbar, sidebar under Navigation menu, settings under Form, and static tags under Badge. Catalogue search/navigation should disclose those relationships. A new mandatory registration layer is not necessary.
- **Keep source distinctions visible.** Documentation's image gallery/comparison examples are broader than its one live SVG story. Dock's edge regions and free-position tiles are real documented capabilities, not decorative variants. Native notification/window behavior requires a stated host adaptation. These should not all be scored as interchangeable missing cards.
- **Avoid stale numeric certification.** Existing inventory counts are lexical snapshots, not evaluated section lists or visual acceptance. Closing this table requires actual source-linked examples plus interaction and visual review, not matching a total example count.
